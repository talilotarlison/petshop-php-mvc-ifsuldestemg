O arquivo `changelog.md` é comumente usado para documentar mudanças em um sistema. Para requisitos, você tem algumas opções de nomes de arquivo padrão ou convencionais que podem ser usados para esse fim, dependendo do tipo e da formalidade do projeto. Aqui estão algumas sugestões com suas finalidades:

---

### 📄 Nomes comuns para arquivo de requisitos:

#### 1. **`requirements.md`**

* **Mais comum em projetos de software.**
* Usado para descrever os requisitos funcionais e não funcionais do sistema.

#### 2. **`specification.md`** ou **`spec.md`**

* Focado em **especificações técnicas** ou funcionais mais detalhadas.
* Pode incluir casos de uso, diagramas, etc.

#### 3. **`system-requirements.md`**

* Para requisitos do sistema em geral (hardware, software, etc.).
* Mais usado quando o projeto é maior ou mais técnico.

#### 4. **`functional-requirements.md`** / **`non-functional-requirements.md`**

* Útil para separar tipos de requisitos.

#### 5. **`software-requirements-specification.md`** ou **`SRS.md`**

* Nome mais formal, especialmente em contextos corporativos ou acadêmicos.
* Segue o padrão IEEE de documentação de requisitos.

---

### 📦 Para projetos em Python:

Se estiver falando de **dependências de software**, o nome padrão é:

* **`requirements.txt`** → Lista bibliotecas/dependências para instalação via `pip`.

---

### 📝 Dica de organização

Se o projeto tiver muitas documentações, pode criar uma pasta chamada `docs/` e organizar os arquivos assim:

```
/docs
  |- changelog.md
  |- requirements.md
  |- specification.md
  |- architecture.md
```
